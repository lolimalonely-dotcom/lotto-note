# คีย์เลข (lotto-note)

เว็บช่วยคีย์รายการเลข แยกตามรอบ เลือกทุกอย่างด้วยการจิ้ม ไม่ต้องจำคำสั่งอะไร
พร้อมสรุปยอดต่อคนและต่อเลขอัตโนมัติ

Next.js 16 · React 19 · Tailwind v4 · Supabase

**ออกแบบให้อ่านง่ายจิ้มง่ายเป็นหลัก** — ตัวอักษรฐาน 17px ปุ่มสูงอย่างน้อย 48px
ทุกอย่างเลือกจากปุ่มหรือดรอปดาวน์ ไม่มีคีย์ลัดที่ต้องจำ

---

## กฎประเภท

| จำนวนหลักของรหัส | ประเภทที่เป็นไปได้                        |
| ---------------- | ---------------------------------------- |
| 2 หลัก           | `บ.` (2 ตัวบน) · `ล.` (2 ตัวล่าง)          |
| 3 หลัก           | `ตรง` · `ต.` (โต๊ด) · `ล.` (3 ตัวล่าง)     |

รหัสกี่หลักก็เทียบกับผลรางวัลของหลักนั้นเท่านั้น **ไม่มีการตัดหลักข้ามกัน** —
เลข 2 หลักไม่ได้เอาไปเทียบกับหลักท้ายของเลข 3 ตัว

พอใส่รหัส ปุ่มประเภทจะขึ้นมาเฉพาะอันที่เป็นไปได้เท่านั้น เลือกผิดไม่ได้เลย
กฎนี้บังคับทั้งฝั่งหน้าเว็บและฝั่งฐานข้อมูล (CHECK constraint) จึงไม่มีทางบันทึกคู่ที่ผิดกฎ

## รอบ

ทุกอย่างแยกตาม **รอบ** — เลือกรอบจากดรอปดาวน์บนสุดของหน้า ทำทีละรอบ

- กด **+ รอบใหม่** เพื่อตั้งชื่อรอบเอง พิมพ์อะไรก็ได้ (เช่น `16 ก.ย. 68`)
- รอบที่สร้างแล้วจะอยู่ในดรอปดาวน์ตลอด เลือกเอาไม่ต้องพิมพ์ซ้ำ จึงไม่มีรอบหลอนจากการพิมพ์ผิด
- สรุปยอดก็แยกตามรอบที่เลือกอยู่

รอบที่มีรายการแล้วจะถูกดึงจากฐานข้อมูลอัตโนมัติ ส่วนรอบที่เพิ่งสร้างและยังไม่มีรายการ
จะเก็บไว้ในเครื่องนั้นจนกว่าจะมีรายการแรก

## วิธีคีย์

1. เลือก (หรือเพิ่ม) **ชื่อรายการ**
2. ใส่ **รหัส** 2 หรือ 3 ตัวเลข — ติ๊ก **กลับเลขให้ด้วย** ถ้าต้องการ ระบบจะโชว์เลยว่าจะได้เลขอะไรบ้าง
3. **จิ้มเลือกประเภท** เลือกได้ทั้งสองอย่างพร้อมกัน
4. ใส่ **จำนวน** — เลือกสองประเภทก็จะมีสองช่อง ใส่คนละจำนวนได้
5. กด **บันทึก** (ปุ่มบอกชัดว่าจะบันทึกกี่บรรทัด รวมเท่าไหร่)

ตัวช่วยความเร็ว

- ประเภทที่ใช้ล่าสุดจะถูกเลือกไว้ให้อัตโนมัติในรอบถัดไป และจำนวนค้างไว้ให้
  คีย์เลขถัดไปจึงเหลือแค่ พิมพ์รหัส → กด Enter
- กด Enter ที่ช่องจำนวนเพื่อบันทึกได้เลย
- มีปุ่ม **ยกเลิกที่เพิ่งบันทึก** เผื่อกดพลาด
- ลบทีละบรรทัดมีหน้าต่างถามยืนยันก่อนเสมอ

**กลับเลข** สร้างเลขสลับหลักทุกแบบที่ไม่ซ้ำกัน
`123` → 123, 132, 213, 231, 312, 321 (6 ตัว) · `112` → 112, 121, 211 (3 ตัว) · `11` → 11
จำนวนที่ใส่คือจำนวน **ต่อเลข 1 ตัว**

## สรุปยอด

- **ยอดรวมทั้งรอบ / จำนวนคน / บรรทัด / เลขไม่ซ้ำ** อยู่บนสุด
- **เลขที่มีคนลงซ้ำกัน** — เรียงจากซ้ำมากที่สุด บอกว่าซ้ำกี่ครั้ง กี่คน รวมเงินเท่าไหร่
  ใช้ดูว่าเลขไหนคนแห่กันซื้อจนต้องระวัง
- **ดูตามชื่อคน** — ยอดรวมของแต่ละคน พร้อมทุกบรรทัดในบิล
- **ดูตามเลข** — แจกแจงทีละบรรทัดว่าเลขนี้ใครลงประเภทไหนเท่าไหร่ พร้อมยอดรวมต่อเลข
- ส่งออก CSV (Excel อ่านภาษาไทยได้เลย) และสั่งพิมพ์ได้

## ตรวจรางวัล

ใส่ผลรางวัลของรอบนั้น (ใส่เท่าที่ออกแล้วก็ได้) แล้วระบบไล่ตรวจทุกบรรทัดให้ทันที

ช่องใส่ผลมี 4 ช่อง แต่ละประเภทเทียบกับช่องของตัวเองเท่านั้น

| ประเภท     | เทียบกับช่อง     | ถูกเมื่อ                            |
| ---------- | ---------------- | ----------------------------------- |
| บ.         | **2 ตัวบน**      | ตรงเป๊ะ                              |
| ล.         | **2 ตัวล่าง**    | ตรงเป๊ะ                              |
| ตรง        | **3 ตัวตรง**     | ตรงเป๊ะ                              |
| ต. (โต๊ด)   | **3 ตัวตรง**     | สลับหลักยังไงก็ถูก รวมถึงตรงเป๊ะด้วย  |
| ล. (3 ตัว)  | **3 ตัวล่าง**    | ตรงเป๊ะ                              |

หน้าตรวจรางวัลแสดง

- **กำไร/ขาดทุนรวม** — ยอดรับทั้งรอบ ลบ ยอดที่ต้องจ่าย
- **ต้องจ่ายใครบ้าง** — แยกเป็นคน พร้อมบรรทัดที่ถูกของแต่ละคนและยอดสุทธิรายคน
- **บรรทัดที่ถูกทั้งหมด** เรียงยอดจ่ายมากไปน้อย

**อัตราจ่าย** (แทง 1 บาทได้กี่บาท) ซ่อนอยู่ใต้ปุ่ม *⚙ ดู / แก้อัตราจ่าย* แก้ได้ตลอด
ค่าตั้งต้น: 2 ตัว 70 · ตรง 500 · โต๊ด 100 · 3 ตัวล่าง 110

ข้อตกลงที่ใช้ในการคิด — แจ้งได้ถ้าร้านคุณคิดต่างจากนี้

- โต๊ดที่ผลออกตรงเป๊ะ **ถือว่าถูก** และถ้าแทงทั้ง ตรง และ โต๊ด บนเลขเดียวกัน ได้เงินทั้งสองทาง
- ช่องผลรางวัลที่เว้นว่างไว้ บรรทัดที่ต้องใช้ช่องนั้นจะยังไม่ถูกตรวจ และมีข้อความบอกว่าค้างกี่บรรทัด

## รันในเครื่อง

```bash
npm install
npm run dev
```

เปิด http://localhost:3000

ถ้ายังไม่ตั้งค่า Supabase แอปจะวิ่ง **โหมดออฟไลน์** เก็บข้อมูลใน `localStorage` ของเบราว์เซอร์
(มีป้าย "ออฟไลน์" กำกับมุมซ้ายบน) ใช้งานได้ครบทุกฟีเจอร์ แค่ข้อมูลอยู่เฉพาะเครื่องนั้น

## ต่อ Supabase

1. สร้างโปรเจกต์ใหม่ที่ [supabase.com](https://supabase.com)
2. **SQL Editor** → วาง [`supabase/migrations/0001_init.sql`](supabase/migrations/0001_init.sql) ทั้งไฟล์ → Run
   แล้ววาง [`supabase/migrations/0002_check_results.sql`](supabase/migrations/0002_check_results.sql) → Run อีกครั้ง
   (0002 เพิ่มประเภท 3 ตัวล่าง และตารางเก็บผลรางวัล/อัตราจ่าย — รันซ้ำได้ไม่พัง)
3. **Authentication → Users → Add user** สร้างบัญชีของตัวเอง (ติ๊ก *Auto Confirm User*)
   — ตั้งใจไม่เปิดให้สมัครเองหน้าเว็บ เพราะ URL เป็นสาธารณะ
4. คัดลอก `.env.local.example` เป็น `.env.local` แล้วใส่ค่าจาก **Project Settings → API**

   ```
   NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGci...
   ```

   ⚠️ ระวังใส่สลับช่อง — URL ต้องขึ้นต้น `https://` และคีย์ต้องขึ้นต้น `eyJ` หรือ `sb_publishable_`
   ถ้าใส่ผิดแอปจะไม่พัง แต่จะขึ้นแถบเหลืองบอกว่าผิดช่องไหน

**ความปลอดภัย** — ทุกแถวผูกกับ `user_id` และเปิด Row Level Security ไว้
แต่ละบัญชีเห็นและแก้ได้เฉพาะข้อมูลของตัวเอง บังคับที่ฝั่ง Postgres ไม่ใช่ฝั่งเบราว์เซอร์

## Deploy ขึ้น Vercel

1. push ขึ้น GitHub
2. Vercel → **Add New → Project** → เลือก repo
3. **Framework Preset ต้องเป็น `Next.js`** — ถ้าขึ้น `Other` ให้เปลี่ยนเอง
   ไม่งั้นจะ build ผ่านแต่เว็บขึ้น 404 เพราะมันไปเสิร์ฟโฟลเดอร์ `public/` แทน
4. ใส่ Environment Variables สองตัวข้างบน ชนิด **Config** (ไม่ใช่ Secret เพราะขึ้นต้นด้วย `NEXT_PUBLIC_`)
   ติ๊กให้ครบทั้ง Production / Preview / Development
5. Deploy — แก้ env ทีหลังต้อง **Redeploy** เสมอ

supabase/migrations/  ← สคีมา + RLS
